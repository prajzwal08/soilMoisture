TerraMind Tokenization — NaN Issue and Fix Plan
================================================
Date: 2026-05-27
Author: Prajwal Khanal


BACKGROUND
----------
After completing all satellite data downloads, the next pipeline step is to
precompute TerraMind features (tokens) for every S2L2A, S1RTC, DEM, and LULC
tile and save them as .pt files to permanent project storage. This is done by
precompute_terramind.py.

A trial run was submitted to the gpu_mig partition (A100 MIG slice, 20 GB VRAM)
processing 3 stations (AmeriFlux_CA-Cbo, CA-DB2, CA-DBB) with batch_size=4.


ISSUE DISCOVERED
----------------
The trial run completed but produced 310 NaN failures out of ~657 S2L2A images
processed (~47% failure rate). The error message in every case was:

    [warn] non-finite values in L12 for YYYYMMDD

S1RTC, DEM, and LULC had no NaN failures. The problem is specific to S2L2A.

Deeper analysis revealed TWO distinct failure categories:
  118 tiles — failed WITH all-zero pixels (swath edge)
  188 tiles — failed WITHOUT any all-zero pixels

Investigation of a failing tile (AmeriFlux_CA-Cbo/S2L2A/20170105.tif) revealed:
  - 3,582 pixels (7.1%) have value = 0 across ALL 12 bands (swath edge)
  - 8 out of 196 token windows fall entirely within this zero region
  - A passing tile (20170323.tif) has 0% zero pixels

Root cause A — swath edge zeros (118 tiles):
  Sentinel-2 L2A fills pixels outside the satellite swath with DN = 0.
  Our pipeline wrote these tiles without a nodata tag (nodata = None).
  Fully-zero patches produce degenerate, uniform activations.

Root cause B — missing input normalization (188 tiles + contributes to A):
  TerraMind's backbone (terramind_v1_base) does NOT apply z-score normalization
  internally. The normalization is only built into the generation model variant
  (terramind_generation.py line 265: d[mod] = (value - mean) / std).
  During TerraMesh pretraining, inputs were z-scored at the dataset level.
  We were passing raw DN values (0–10000) directly to the backbone.
  Without normalization, input magnitudes are ~1000× larger than expected,
  causing fp16 attention softmax overflow (max fp16 = 65504) on any tile with
  high or uniform reflectance — cloud cover, snow, bright surfaces.
  This is confirmed by inspecting the pretraining stats stored in
  terramind_register.py: v1_pretraining_mean["untok_sen2l2a@224"] values are
  in raw DN units (1390–3163), showing the model was trained on normalized
  inputs using those exact statistics.


WHAT TERRAMESH DOES
-------------------
TerraMind v1 was pretrained on TerraMesh, an IBM/ESA dataset built on top of
SSL4EO-S12 v1.1. The TerraMesh paper (arXiv 2504.11172) documents the following
S2L2A preprocessing pipeline:

1. Cloud and invalid pixel detection via SEnSeIv2
   SEnSeIv2 (Francis et al., IEEE TGRS 2024) is a sensor-independent cloud
   masking model that classifies every pixel into 6 classes:
       0 = land, 1 = water, 2 = snow, 3 = thin cloud,
       4 = thick cloud, 5 = cloud shadow
   A separate no-data class (6) is added for pixels with all bands = 0.
   These masks are stored as metadata alongside each S2L2A tile in TerraMesh.
   Native S2 SCL flags are explicitly NOT used — the paper notes they are
   unreliable.

2. Patch-level quality filtering
   Any patch where more than 1% of pixels are NaN (invalid) is discarded
   entirely from the training corpus.

3. NaN filling for small invalid regions
   Patches with ≤ 1% NaN are retained. Remaining NaN pixels are filled via
   nearest-neighbour interpolation before normalisation.

4. Z-score normalisation
   Per-band normalisation using TerraMesh pretraining statistics (means and
   stds over the training corpus). Raw DN values (int16, 0–10000) are
   normalised internally by the TerraMind tokenizer.

The consequence: TerraMind was NEVER trained on tiles with large all-zero
regions. Any such tile is severely out-of-distribution and produces NaN outputs.
The ~47% failure rate in our trial reflects this — many winter/early-season
S2L2A acquisitions in Canada have partial swath coverage or heavy cloud cover
that our pipeline passes through unchecked.


OUR FIX — MATCHING TERRAMESH EXACTLY
--------------------------------------
Two complementary fixes, both needed:

FIX A — Z-score normalization (addresses root cause B, also stabilises A)
  Added to precompute_terramind.py in TerraMindEncoder:
  - Precompute per-modality (mean, std) tensors of shape (C,1,1) in __init__
  - In forward(), before calling backbone: patch = (patch - mean) / std
  - Stats from terramind_register.py v1_pretraining_{mean,std}:

  Modality  Bands  Mean range (raw units)       Std range
  --------  -----  ---------------------------  ---------------
  S2L2A      12    1390–3163 (DN, 0–10000)      1334–2142
  S1RTC       2    -10.93, -17.33 (dB)          4.39, 4.46
  DEM         1    670.7 (m)                    951.3
  LULC        1    0 (v1_5: mean=0, std=1)      identity

  LULC uses class labels (small integers, no overflow risk), so no normalization.

FIX B — SEnSeIv2 cloud masking (addresses root cause A, improves quality)
  We use SEnSeIv2 directly — the same model TerraMesh used:

    Model: SEnSeIv2-SegFormerB2-alldata-ambiguous
    GitHub: https://github.com/aliFrancis/SEnSeIv2
    Weights: https://huggingface.co/aliFrancis/SEnSeIv2 (auto-downloaded)

  Why we can use it:
  - Installed in a dedicated conda env (sensei)
  - GPL-3.0 licence is fine for academic research
  - Sensor-independent: handles our 12-band S2L2A tiles (no B10) natively
  - transformers pinned to 4.46.3 in sensei env (v5.x broke SEnSeIv2)

  Smoke test result (2026-05-27):
    FAILING tile (20170105, Canada, January):
      land=0.8%  thin cloud=46.2%  thick cloud=32.3%  shadow=13.4%  nodata=7.1%
      → ~99% invalid; correctly flagged for discard by TerraMesh rule
    PASSING tile (20170323, Canada, March):
      land=91.9%  thick cloud=3.7%  shadow=4.5%  nodata=0%
      → clean tile, passes with NN-fill

  Output class encoding (full 7-class, matches TerraMesh):
      0 = land, 1 = water, 2 = snow/ice, 3 = thin cloud
      4 = thick cloud, 5 = cloud shadow, 255 = nodata (all bands == 0)
  Invalid classes in precompute_terramind.py: {3, 4, 5, 255}


IMPLEMENTATION STEPS
--------------------
STEP 1 — Z-score normalization ✓ (2026-05-27, precompute_terramind.py)
  Applied in TerraMindEncoder.forward() for S2L2A, S1RTC, DEM.
  Expected to eliminate the 188 non-zero NaN failures entirely.
  Also stabilises all-zero swath edge tiles (0 normalises to ~-0.7 to -2.4 σ,
  finite values — no overflow even before cloud masking is applied).

STEP 2 — Precompute cloud masks (SLURM CPU array job)
  - cloud_masking_inference.py rewritten and smoke-tested ✓ (2026-05-27)
  - Run as a thin-node CPU SLURM array job across all 1048 stations
  - Output: /gpfs/scratch1/shared/pkhanal/satellite/{station}/CloudMask/YYYYMMDD.tif
  - Zero GPU cost. SEnSeIv2 runs on CPU for 224×224 patches.

STEP 3 — Use masks in precompute_terramind.py
  - Load CloudMask/YYYYMMDD.tif alongside each S2L2A tile
  - Build invalid pixel mask: classes {3, 4, 5, 255} → invalid
  - If > 1% invalid: skip tile entirely (TerraMesh curation rule)
  - If ≤ 1% invalid: fill with nearest-neighbour (scipy distance_transform_edt)
  - Fallback if no CloudMask: use (arr == 0).all(axis=0) as nodata proxy

STEP 4 — Trial re-run
  - Re-run precompute_terramind.py --trial 3 after Step 1 is committed
  - Expect NaN count ≈ 0 after normalization fix
  - Then submit cloud masking SLURM job, then full tokenization
