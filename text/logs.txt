Root cause of silent logs — conda run stdout buffering:
  Every previous job showed only 3 lines (bash echo) then silence until job exit.
  Root cause: conda run internally pipes child stdout and batches it until process

    hits a new un-cached zarr chunk on GPFS, queue drains in 8×285ms = 2.3s, then
    GPU stalls waiting. Stalls every 8 batches until all chunks page-cached (~batch 34).

Memory architecture confirmed:
  /dev/shm is 378 GB total (50% of 792 GB node RAM) — not 1 TB as assumed.
  L12 preload uses 182 GB → only 192 GB free. L3+L6+L9 ≈ 546 GB → cannot preload.
  Page cache handles L3/L6/L9: after epoch 1 warmup, zarr reads hit RAM at same speed
    as memmap. Converting zarr → GPFS memmaps provides no benefit (page cache already
    does this). Current architecture is correct and complete for hardware available.
  GPFS memmaps are only beneficial on local storage (NVMe); Snellius H100 nodes have
    no local NVMe — scratch is GPFS network storage.

Worker / prefetch tuning analysis (decided NOT to change):
  Each queued batch costs ~2.5 GB in DataLoader IPC Shmem.
  Current (8w × pf=2): 16 queued batches × 4 ranks = 160 GB IPC Shmem.
  Proposed 10w × pf=3: 240 GB IPC (+80 GB), 108 GB headroom — technically safe.
  Proposed 8w × pf=4: 320 GB IPC (+160 GB), only 28 GB headroom — risky on full run.
  Proposed 12w × pf=8: 960 GB IPC → OOM.
  Decision: keep 8w × pf=2. GPFS stalls in epoch 1 = ~60s total overhead across a
    700-min full run = 0.1% of training time. Not worth RAM risk or added complexity.

Memmap warning fix:
  torch.from_numpy() on mode='r' /dev/shm memmaps triggered PyTorch non-writable
    warning, printing source line 215 of dataset.py 39× in log output.
  Fix: warnings.filterwarnings("ignore", message=".*non-writeable.*") in dataset.py.
    Warning is benign: tok is immediately copied into pre-allocated l12 buffer.

Why the original OOM crash (job 23733182) cannot recur:
  Old behaviour: _l12_cache populated lazily per DataLoader worker. Each of 4 ranks
    independently loaded L12 for every station it sampled → progressive AnonPages growth
    until batch ~600 when all stations had been sampled. 600 stations × 300 MB × 4 ranks
    = ~728 GB L12 in AnonPages alone → hit 384G cgroup limit at batch 603.
  New behaviour: rank 0 preloads ALL stations' L12 to /dev/shm before DDP init.
    All 4 ranks read via np.memmap(mode='r') → OS shares one physical copy in Shmem.
    L12 cost: 182 GB Shmem (counted once, not 4×). No lazy loading, no progressive growth.
  L3/L6/L9 zarr reads during training land in OS page cache (reclaimable, not counted
    by SLURM cgroup). RAM profile is flat from batch 1 onward.
  Current full-run memory budget:
    L12 Shmem:         182 GB
    DataLoader IPC:    160 GB
    AnonPages:        ~130 GB
    Total counted:    ~472 GB / 700 GB → 228 GB headroom, no growth expected.

--- Code review fixes (same session, continued) ---

Job 23751109 failed — TCPStore timeout after 600s:
  Root cause: rank 0 preloaded ~120GB to /dev/shm while ranks 1-3 sat inside
    dist.barrier() waiting for rank 0 to store its NCCL unique ID. TCPStore times
    out after 600s independently of NCCL_TIMEOUT.
  Fix: moved preloading to BEFORE dist.init_process_group(). Ranks 1-3 now spin
    on a sentinel file (.done) with sleep(2) — no NCCL involved, no timeout risk.

Additional fixes from structured code review:
  1. NLL loss — replaced softplus+1e-6 variance with log-variance parameterization.
     NLL = 0.5*log_var + 0.5*(y-mu)^2*exp(-log_var). Avoids division by near-zero
     variance (gradient ~1e9 under softplus) → stable gradients in bfloat16.
     Decoder bias init -3.7 unchanged: exp(-3.7)≈0.025, σ≈0.16 m³/m³.
  2. log_var bounded via tanh(raw/10)*10 — soft clamp to (-10,10), σ∈(0.007,148).
     Hard clamp rejected: kills gradient at boundary (dead neuron). tanh preserves
     non-zero gradient everywhere.
  3. S2 NaN guardrail — load_s2_rolling_zarr was missing the isnan check that S1
     already had. Swath-edge corruptions would silently corrupt batch embeddings.
  4. All-cloud NaN gradient — spatial_pyramid_pool: -inf → -1e4 in attention mask.
     -inf + softmax = NaN; autograd cannot backprop through NaN in bfloat16.
  5. Worker seed offset — worker_init_fn: seed += worker_id for explicit per-worker
     numpy/random divergence.
  6. ulimit -n 65536 — slurm/train.sh: 612 stations × 3 memmap keys × 8 workers
     ≈14k FDs; default SLURM ulimit 4096 would crash dataset init on full run.
  7. non_blocking=True — all .to(device) calls in train loop and evaluate. With
     pin_memory=True already set, overlaps PCIe transfer with GPU compute.
  8. ubRMSE deflation guard — compute_metrics: skip stations with <2 samples.
     Single-sample station has zero anomaly → deflates metric; guard now explicit.
  9. Architecture note (no change): 14×14 U-Net skip connections provide semantic
     depth but not high-frequency spatial edges. Acceptable for soil moisture;
     revisit for Phase 2 flux estimation where spatial sharpness matters.

2. Cloud mask: was (cm==0).all() treating water/snow as invalid → fixed to bad_frac<=0.01
   for classes {3,4,5,255} (thin cloud, thick cloud, shadow, nodata)
3. Missing modality embeddings: ERA5, S2-hist, S1-hist tokens had no type embeddings —
   transformer couldn't distinguish them → added hist_modality_emb, era5_modality_emb
4. RNG duplication across DataLoader workers: self._rng.Random() duplicated on fork →
   replaced with torch.rand(1).item() + worker_init_fn seeding
5. xarray in __getitem__: ERA5/SIF/TWSA/labels opened per sample → moved to __init__ numpy caches
6. Label xr.Dataset cache: open file handles across fork → numpy arrays, close immediately
7. _in_window leap year bug: DOY comparison included 366 days for leap-year boundaries →
   replaced with _window_datetimes() using timedelta(364) arithmetic
8. _window_ints leap year bug: same root cause → now delegates to _window_datetimes()
9. S1 glob() in __getitem__: GPFS metadata query per sample → _resolve_pt_paths() in __init__
10. log_var clamping: clamp only in loss function created dead neurons (zero gradient outside
    [-6,6]) → moved clamp to UNetDecoder.forward before returning
11. _rel_pos leap year overflow: DOY formula could return values outside [0,364], crashing
    nn.Embedding(365) → replaced with 364-(target_dt-acq_dt).days datetime subtraction
12. ERA5 padding mask: slot-index compared with calendar DOY → model was blind to recent
    weather (target_doy=100 masked 265 most-recent ERA5 slots including target day itself) →

    acquisition — breaks at year boundary (Dec DOY~350 > Jun DOY~180 even if Jun is newer) →

## 2026-06-03 — ERA5-Land NaN fix for 3 coastal stations

### Root cause
check_dataset job 23421285 found 26 ERA5 NaN errors across train/val splits.
All from 3 stations: ISMN_SCAN_Combate (val), ISMN_SNOTEL_PortGraham (train),
ISMN_USCRN_Cape-Charles-5-ENE (oos).
Pattern: 18/19 ERA5 variables entirely NaN, only tp_sum valid.

Root cause: these are coastal/island stations whose coordinates fall on ocean pixels
in the ERA5-Land 0.1° grid. ERA5-Land masks ocean cells. The old CDS download script
used two separate datasets — Group A (derived-era5-land-daily-statistics) returned
all-NaN for ocean pixels, while Group B (reanalysis-era5-land-timeseries) happened
to return valid tp values, creating a mixed result.

### Fix
Rewrote download_era5land_gee.py with a 3-strategy fallback chain per station:
  1. ERA5-Land point query (0.1°) — default
  2. ERA5-Land 25 km buffer + mean of valid nearby land pixels
  3. ERA5 reanalysis (0.25°, global, no land mask)
  4. Flag for exclusion if all strategies return NaN

All 3 stations resolved via Strategy 2 (buffer 25km) — nearby land pixels had valid
data. Strategy 3 was not needed.

Re-downloaded via: download_era5land_gee.py --stations ISMN_SCAN_Combate,
ISMN_SNOTEL_PortGraham,ISMN_USCRN_Cape-Charles-5-ENE --consolidate --era5-only

Consolidated files overwritten (0 NaN in all variables):
  sm_only/ISMN_SCAN_Combate/ERA5Land/meteo_20190101_20241231.nc        (2192 days)
  sm_only/ISMN_SNOTEL_PortGraham/ERA5Land/meteo_20140101_20221231.nc   (3287 days)

  fall back to most recent image regardless of cloud cover. This replaces the previous
  `load_recent_skip_features_zarr` approach which ignored cloud quality.
- `anchor_orbit` encoding changed from bool (is_s1: True/False) to 3-class int (0=S2, 1=S1_asc,
  2=S1_desc) so the spatial modality embedding can distinguish the two orbit directions.
- ContextFormer-style random masking (p=0.5, training only) AND-ed with real nodata masks before
  pyramid pooling — forces the model to learn spatial redundancy robustly.
- DEM/LULC are static per station, so their token_mask is written once as a (14,14) bool array rather
  than per-acquisition.

## 2026-06-12 — Architecture & Code Critique Q&A

### Question (external review)

A detailed technical and architectural critique was raised covering the following points:

I. Technical (Code Mechanics)
  1. RAM Limits and the _l12_cache: eager-loading the full L12 history (S2 + S1-ASC + S1-DESC) for
     every station into RAM during __init__ risks OOM at scale. Suggested fix: use numpy mmap_mode='r'
     instead of zg["s2/l12"][:] eager copies.
  2. DOY Positional Encoding Discontinuity: sinusoidal_pe feeds absolute DOY (1-365) into a standard
     Transformer PE, which is not periodic. DOY 365 and DOY 1 get very different embeddings even though
     they are temporally adjacent. Suggested fix: circular encoding sin/cos(2π·DOY/365.25).
  3. Hardcoded Magic Numbers in Pyramid Pooling: spatial_pyramid_pool uses explicit indices
     _pool(6,8,6,8) etc., rigidly coupling the code to a 14×14 grid. Suggested fix:
     torch.nn.AdaptiveAvgPool2d.
  4. Uncertainty Clamping (log_var): .clamp(-6.0, 6.0) kills gradients outside bounds (dead neurons).
     Suggested fix: Softplus activation to ensure positivity with gradient flow everywhere.

II. Architectural (Model Design)
  1. Point-to-Pixel Supervision on a UNet: UNet generates a 224×224 map but losses only compute
     gradients at the single center pixel (row=col=112). No pressure for spatial coherence in the
     other 50,175 output pixels.
  2. Temporal-to-Spatial Bottleneck: 196 target spatial tokens must absorb 365-day ERA5 history and
     satellite history via self-attention; high-frequency historical data may be diluted before
     reaching the UNet bottleneck.
  3. Skip Connections Bypass Temporal Context: UNet skip connections (L3/L6/L9) come from the static
     anchor acquisition and completely bypass the Temporal Transformer, so high-res decoder layers
     have no knowledge of recent weather or historical soil state.

Final question: given that the UNet output is only supervised at the center pixel, how is spatial
coherence across the 224×224 map validated?

---

### Answer

**I.1 RAM / L12 cache — Partially valid, but already partially addressed**

The critique is right that eager L12 loading is dangerous at scale. However the code already has two
mitigations not acknowledged by the critique:
- _load_pt (dataset.py:103) already uses mmap=True (PyTorch-level memory mapping, not eager loading).
- DISABLE_L12_CACHE=1 env var exists as an explicit escape hatch.
The real risk is whether __init__ does zg["s2/l12"][:] (a full array copy into RAM) rather than keeping
a lazy zarr reference. That specific path in load_s2_rolling_zarr:296 correctly avoids the copy when
l12_np is None. The mmap suggestion is already implemented for the .pt path.

**I.2 DOY PE discontinuity — Valid, but only applies to ERA5/SIF/TWSA**

sinusoidal_pe (model.py:42) does treat DOY as a linear scalar, creating a real discontinuity at year
boundaries. However, satellite history tokens do NOT use sinusoidal_pe — they use rel_pos_emb (a
learned relative-position embedding, model.py:494,504). The discontinuity only affects ERA5
(model.py:519), SIF (model.py:545), and TWSA (model.py:563). The circular encoding fix is correct and
straightforward. This is a real bug for training across year boundaries and worth fixing:

  # Replace sinusoidal_pe for ERA5/SIF/TWSA with:
  sin_enc = torch.sin(2 * math.pi * doys.float() / 365.25)
  cos_enc = torch.cos(2 * math.pi * doys.float() / 365.25)
  # then project [sin, cos] -> d_model via a small MLP

**I.3 Hardcoded pyramid indices — Valid concern, wrong fix**

The indices at model.py:103-106 are hardcoded for 14×14 and are a real brittleness. But the suggested
fix (AdaptiveAvgPool2d) cannot replace the existing implementation because _pool uses learned attention
weights from self.s2_pyramid_attn (nn.Linear(768,1)). AdaptiveAvgPool2d only does uniform pooling. The
right fix is to parameterize the grid size while preserving attention-weighted pooling:

  G = int(tokens.shape[1] ** 0.5)  # 14 for 196-token grid
  c = G // 2
  # compute scale bounds from G dynamically

**I.4 log_var clamping — Critique partially misses what the code already does**

The comment at model.py:195-198 already diagnoses the "dead neuron via loss-side clamping" problem and
explicitly moved the clamp to the model output to ensure gradients flow through the network. The
Softplus suggestion is mathematically cleaner (no zero-gradient regions anywhere), but changes the
parametrization (would learn variance directly rather than log-variance). Given the bounds [-6,6]
correspond to σ² ∈ [0.0025, 403] — a very wide range for soil moisture — this is a low-priority fix.

**II.1 Point supervision on a UNet — The most valid critique, the most important**

Confirmed: masked_huber_loss and masked_nll_loss both extract a single pixel (row=112, col=112) before
computing loss. The entire UNet decoder (~4M parameters across 4 upsampling stages) receives gradient
from exactly one pixel per sample. This means the model can satisfy the loss with a spatially uniform
sheet at the station value. Practical options in order of cost:
  1. Total Variation regularization: penalize |∇SM_map|. Low cost, physically justified (SM is
     spatially coherent).
  2. LULC/DEM consistency loss: pixels with identical LULC class and similar elevation should have
     similar SM. Uses data already in the pipeline.
  3. FiLM-modulated skip connections (see II.3 below).

**II.2 Temporal-to-Spatial bottleneck — Less concerning than stated**

The architecture is well-suited for cross-modal fusion: the 196 spatial tokens sit inside the
bidirectional Transformer alongside all 365 ERA5 tokens and satellite history tokens, able to attend
to any of them (model.py:644). This is closer to a ViT fusion pattern than a bottleneck. Whether 6
layers is sufficient is a hyperparameter question, not a fundamental design flaw.

**II.3 Skip connections bypass temporal context — Valid and tractable to fix**

_get_skip_connections (model.py:429) loads L3/L6/L9 from the static anchor acquisition with no ERA5
conditioning. The high-resolution UNet layers are driven entirely by "what did the satellite see on the
anchor day" with no knowledge of recent weather. FiLM modulation is the right fix: take a summary
vector from the transformer context (e.g., mean-pooled ERA5 output tokens), project to (scale, shift)
via a small linear layer, and apply to each skip before concatenation. ~100 lines of code.

**On spatial validation**

Since the loss only supervises the center pixel, the map outputs are currently unvalidated beyond that
point. Practical approaches:
  1. Cross-station tiling: some ISMN stations are within a few km of each other. If two stations share
     overlapping tile footprints, the model's predicted SM at each station's pixel can be compared to
     the observed SM at that station (without ever training on that relationship).
  2. Visual audits against LULC: generated SM maps should show lower values over urban/bare soil and
     higher over vegetated pixels in the same tile.
  3. Lag-correlation with precipitation: SM at any pixel should show a positive response to ERA5 tp_sum
     within a few days. Computable for every pixel in held-out tiles.
  None of these replace dense labels, but they would falsify the "flat sheet" failure mode.

**Priority ranking of fixes**
  High: II.1 (point supervision) — add TV or LULC/DEM consistency loss before scaling up training.
  High: I.2 (circular DOY encoding) — real bug for cross-year samples, easy to fix.
  Medium: II.3 (FiLM-modulated skip connections) — ~100 lines, directly improves temporal context in
          high-res decoder layers.
  Low: I.3 (parameterize pyramid grid size) — brittleness, not a current bug.
  Low: I.4 (Softplus for log_var) — current clamping is defensible; Softplus is cleaner but non-urgent.

All 5 fixes implemented in commit bce7fd5 (model.py, train.py):
  - circular_doy_pe: ERA5/SIF/TWSA tokens now use sin/cos(k*2π*DOY/365.25) harmonics
  - Softplus log_var: UNetDecoder outputs log(softplus(x)+ε); clamp removed from loss
  - FiLMLayer: temporal context (mean-pooled non-spatial transformer output) injected
    into L9/L6/L3 skip connections via learned scale+shift
  - total_variation_loss: λ_tv=0.001 default, tunable via --lambda-tv
  - spatial_pyramid_pool: grid side G=int(N_tok**0.5), works for any square token grid

  Train IPC drops from 440 GB → 242 GB.
  New boundary peak: 607 GB → 183 GB headroom vs 790G.

Fix 2: gc.freeze() inserted in train.py after both datasets are built, before
  DataLoader forks workers.
  Mechanism: gc.freeze() moves all existing Python objects into a permanent GC
  generation that the collector never scans. Without it, the GC traversal touches
  refcount fields on CoW-shared pages → kernel gives each worker a private RSS copy
  → RAM blowup across 32 worker processes (observed in earlier sessions).
  With gc.freeze(): refcount fields are never touched after fork → CoW pages stay
  shared → ~159 GB rank heap stays as one physical copy.

--- DDP rank imbalance fix (model.py) ---

Symptom: G0 = 100% GPU util, G3 = 30% at DDP gradient barrier.
Root cause: _pyramid_from_l12() in model.py used .nonzero() to find valid
  (non-padded) acquisitions. nonzero() output size depends on data → PyTorch
  must sync CPU↔GPU to determine output shape → different ranks stall for
  different durations depending on how many valid acquisitions they have →
  imbalance at the DDP allreduce barrier.

Fix: removed .nonzero() and all gather/scatter logic (~22 lines deleted).
  New approach: run spatial_pyramid_pool on ALL rows (padded l12=zeros →
  zero output from pool), then multiply by flat_valid[:, None, None] to zero
  out padded slots. No GPU sync required. All ranks process the same number
  of rows (MAX_S2 + MAX_S1) regardless of how many are valid.
  Zero-init invariant documented in model.py comment: padded l12 slots must
  be initialised to zero (guaranteed by dataset.py pre-allocation).

--- Fix: move all pyramid pooling from GPU to CPU (in DataLoader workers) ---

Key insight: the 30 MB/sample IPC cost comes from transferring full L12 token arrays
(s2_l12 [MAX_S2,196,768] + s1_l12 [MAX_S1,196,768]) through shared memory. If pyramid
pooling is done in the worker before IPC, each sample sends only a pooled tensor
(MAX_S2,4,768) + (MAX_S1,4,768), reducing per-sample IPC from 30 MB → ~2 MB (15×).

New function: _cpu_pyramid_pool(l12, token_mask) → (M, 4, 768)
  Static masked-mean over 4 nested spatial windows (widths [1,3,5,7]) on the 14×14
  token grid. Runs in DataLoader worker on CPU before IPC, no GPU involved.

S2/S1 random token dropout (ContextFormer augmentation):
  Training only: 50% random dropout applied to token_mask before pooling for S2 and S1.
  Simulates cloud cover and orbit gaps. Controlled by training: bool=False param in

--- ROOT-CAUSE FINDING: only 195 parameters are depth-specific ---

train.py CONFIG never sets use_cls_depth, so it falls through to the default
False (model.py:204). That selects the else-branch of the decoder head:

    model.py:241    self.head = nn.Conv2d(c[3], n_depths, 1)
    with dec_ch = (512, 256, 128, 64)  ->  Conv2d(64, 3, 1)

    depth-specific params:        195   (192 weights + 3 biases)
    shared by all three depths: 50,050,749
    => 99.9996% of the network receives ONE summed gradient.

All three depths are three linear read-outs of the SAME shared 64-channel
feature map. A depth difference can only be expressed as a different linear
projection of one representation.

Corroborated independently by the DDP warning already in the job log:
    "grad.sizes() = [3, 64, 1, 1]"
which is exactly this head.

Interpretation: train_loss falling to 0.0004 while 30-100 val DEGRADES is not
an underfitting signature. The shared trunk is being fit to the abundant
surface labels and is dragging the deep read-out along with it. That is what
195 depth-specific parameters would predict.

--- Why per-depth LOSS cannot fix this (settled this session) ---

per_depth_loss=True (train.py:210) computes Huber separately per depth then
takes the mean (model.py:735-748). That gives each depth EQUAL WEIGHT in one
shared gradient. It does NOT produce separate updates per depth.

"Train each depth separately" is not actually available here:
  - L0.backward(); L1.backward(); L2.backward(); step()
    PyTorch accumulates grads, so this computes grad(L0+L1+L2) — mathematically
    IDENTICAL to the current mean, up to the 1/3 scale. Just slower.
  - Stepping between each backward makes the result order-dependent and triples
    the effective LR. Strictly worse, and still moves all 50M shared params.
Separate training requires separate PARAMETERS. The lever is architecture, not
the loss function.

--- Open caveat: information ceiling vs capacity limit ---

More depth capacity only helps if the deep signal is present but unextracted.
Physically:
  - S2 optical  -> surface reflectance, nothing below ~1 cm
  - S1 SAR      -> C-band, a few cm at most
  - 30-100 cm information can ONLY come from ERA5-Land, soil texture, and
    temporal memory.
No head architecture can pull deep moisture out of satellite tokens. If the
ERA5/soil/temporal pathway is the bottleneck, use_cls_depth buys a better
read-out of information the trunk never encoded, and it will plateau again.

Per-depth TRAIN loss is the diagnostic that separates the two:
   train 30-100 high & flat + val high  -> underfitting: capacity or info ceiling
   train 30-100 low        + val high   -> label scarcity / generalisation
These need opposite fixes, and today we cannot tell which we have.

If use_cls_depth does NOT move it, the next lever is physically motivated
rather than more parameters: CASCADE the depths — predict 10-30 as a residual
on 0-10, and 30-100 as a residual on 10-30 — so deep predictions inherit the
well-constrained surface representation instead of learning independently.
Premature until the diagnostic says capacity was the problem.
